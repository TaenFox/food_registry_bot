# ADR-037. Чтение дневника из Telegram Mini App

Mini App отдаётся как статическая страница. На том же HTTPS-адресе доступен
`GET /api/diary`. Обработчик запускается вместе с ботом во внутренней сети
Docker и использует ту же базу, правила доступа и расчёт пищевого дня.

Запрос передаёт подписанные данные Telegram в заголовке `Authorization: tma …`.
Сервер проверяет подпись и время выдачи. Данные входа действуют до одного часа,
с допуском расхождения часов до 30 секунд в будущее. Идентификатор пользователя
берётся из проверенных данных Telegram. Без подтверждённого входа или доступа
сервер возвращает только код ошибки. Ответы запрещено кэшировать.

API возвращает пять пищевых дней, заканчивая текущим. Для каждой включённой
метрики КБЖУ он возвращает факт, цель, процент и пороги в исходных единицах.
Цель читается из снимка соответствующего дня. Калорийная цель включает
сохранённую тренировочную компенсацию по тому же правилу, что и дневной отчёт.
Допуск берётся из текущих настроек отчёта. Чтение не создаёт снимки. При
отсутствии сохранённой цели или факта процент отсутствует.

Приём пищи соответствует одной сохранённой записи еды, а блюда — её позициям.
Дневные итоги считаются по тем же правилам полноты, что и в боте. Список
приёмов показывает и неполные записи, отмечая отсутствующую калорийность.
