# ADR-011: Admin Access Control and User Allow/Deny

## Context

Боту нужны минимальные административные функции в Telegram:

- фиксированный админ, задаваемый в конфиге;
- возможность админа разрешить пользователю пользоваться ботом;
- возможность админа запретить пользователю пользоваться ботом.

При этом ролевая модель должна оставаться максимально простой:

- права админа не управляются из бота;
- админ определяется только конфигом;
- доступ обычных пользователей управляется отдельной моделью доступа.

## Decision

### 1. Админы задаются только в конфиге

Админы задаются списком `telegram_user_id` в конфиге через `ADMIN_USER_IDS`.

Для проверки прав используется только `telegram_user_id`, а не `username`, потому что `username` может меняться и не является стабильным идентификатором доступа.

### 2. Доступ пользователей хранится в БД

Для обычных пользователей вводится отдельная таблица доступа.

Она хранит:

- `telegram_user_id`;
- `username` для наблюдаемости;
- `is_allowed`.

Отсутствие записи в таблице означает, что доступ не разрешён.

Если новый пользователь впервые пишет боту без разрешения, приложение создаёт или обновляет для него запись `user_access` со значением `is_allowed = false`, чтобы этот пользователь попадал в admin-обзор и требовал явного решения админа.

### 3. Поведение для неразрешённых пользователей

Если пользователь не является админом и не имеет разрешённого доступа:

- бот не выполняет команды;
- бот не обрабатывает сообщения;
- бот не создаёт journal entries;
- бот отвечает отказом в доступе.

Это правило распространяется и на `/start`, и на `/health`, и на обычные сообщения.

### 4. Admin команды первого шага

На первом шаге добавляются admin-команды:

- `/admin_allow <telegram_user_id>`;
- `/admin_deny <telegram_user_id>`.
- `/admin_users`.
- `/admin_backfill_nutrition [LIMIT]`.

Команды доступны только админам.

### 5. Роль админа не управляется из бота

Команды для назначения или снятия admin-прав не вводятся.

Если состав админов нужно изменить, это делается только через конфиг и перезапуск приложения.

## Consequences

- Управление доступом становится достаточно простым для локальной эксплуатации и первых product-итераций.
- Админский контур не смешивается с пользовательской моделью журнала.
- Следующие admin-функции, включая backfill nutrition, можно добавлять поверх уже существующего admin access layer без пересмотра базовой модели ролей.
